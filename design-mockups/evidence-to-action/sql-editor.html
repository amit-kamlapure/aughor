    The SQL Editor, as EVIDENCE → ACTION v2.0 §10 draws it

    One real query on theLook: daily orders, revenue and order value for 20 Oct – 8 Nov. It ran on 9 Nov at 19:40 UTC, took 1,579 ms, returned 20 rows and left signed receipt 4c2e2a494780. Click a column header or a column in the table list to open the inspector. The tabs under the editor switch views of the same run; switching never runs the query again.

    What the doc changed here

    1. Run states say exactly what happened, and no more. The Execution tab shows sent → succeeded → receipt signed with real times. It draws no validating or queued stage, because none is recorded, and it says none recorded for guard checks.
    2. Results are one run seen five ways: Results, Chart, Profile, Execution and Logs. The Profile is computed from the 20 loaded rows and says so.
    3. The grid says how much it holds ("20 of 20 rows · complete"), whether the data is live or cached, and that "Filter loaded rows" only filters what's on screen.
    4. A column opens the inspector, and the inspector reads the receipt's lineage. revenue comes from order_items.sale_price as output, and it points out that the governed Revenue metric uses the same rule (cancelled lines left out).
    5. Numbers show no currency sign. The query doesn't know its unit, so the grid doesn't claim one.
    6. One side pane below 1600px: the table list and the inspector take turns.

    What already exists in Pramanyx

    • The editor (CodeMirror 6, dialect-aware, with a formatter), tabs, history, saved queries, a catalog rail and the TanStack results grid with its column menus. The doc accepts CodeMirror 6, so none of it is replaced.
    • The signed receipt and its column lineage. Today they're one link away; here they're the Execution tab.

    What's new

    • The Chart, Profile, Execution and Logs tabs next to Results.
    • The title row (name, draft or saved, owner) and the status strip.
    • The column inspector, with lineage and the governed-metric pointer.
